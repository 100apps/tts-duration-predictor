A完整版：IndexTTS2.5 全流程

自回归 TTS：文字 → 语义 token → 梅尔谱 → 波形。时长在 T2S 结束时即已确定，后面只是渲染。

① 输入层 官方

  • text：待合成文字（支持发音标注 <字|拼音>）
  • spk_audio_prompt：音色参考音频（3~5 秒即可克隆）
  • emo_audio_prompt / emo_vector(8维) / emo_text：情绪来源三选一，可 emo_alpha 调强度
  • duration_factor：语速倍率，0.5–2.0，>1 变慢
  • lang：ZH / EN / JA / ES / AR
↓

② 文本前端 社区资料

  • 中文字符 + 拼音混合建模（解决多音字，如"银行"不读错）
  • 输出文本 embedding 序列 Etext
↓

③ 说话人编码器 论文

  • Conformer-based speaker perceiver 从参考音频提取 timbre embedding c
  • 只编码音色，与情绪解耦（训练用 GRL 对抗）
wav → Conformer → c ∈ R^d（音色向量）
↓

④ 情绪编码器 论文

  • Conformer-based emotion perceiver 提取 emotion embedding e
  • 支持：情绪参考音频 / 8维向量 / 自然语言描述（Qwen3 微调软指令，需 use_qwen_emo）
  • 与音色解耦：同一音色可配任意情绪
↓

⑤ 时长编码（核心创新） 论文

  • p = Wnum·h(T)：从目标语义 token 数 T 算出的专用时长 embedding
  • 技巧 Wsem = Wnum：时长表与语义位置表绑死，自回归生成时位置信息与目标时长精确对齐
  • 双模式：精准模式（指定 T）/ 自由模式（训练时 30% 概率把 p 置零，不指定）
输入序列 = [c+e, p, e(BT), E_text, e(BA), E_sem]
↓

⑥ T2S：GPT 自回归生成 论文 官方

  • ~0.8B 参数 GPT backbone，逐 token 生成 语义 token（MaskGCT semantic codec）
  • 每个 token 一次前向，串行不可并行 —— 全管线最耗时的环节
  • ⏱️ 时长在此刻完全确定：token 数 T × 每 token 秒数（约 48–50 tokens/秒 估算，需实测标定）
[c+e, p, e(BT), E_text, e(BA)] → 自回归 → S = (s₁…s_T)，T 即时长
↓

⑦ S2M：流匹配解码 官方

  • Flow-matching 模型：语义 token → 梅尔频谱图
  • 非自回归但需十几~二十次迭代，并行处理整段
  • 不改变总时长（帧率固定，确定性上采样）
↓

⑧ 声码器 官方

  • BigVGAN：梅尔谱 → 22.05kHz 波形，单次前向，很快
  • 不改变总时长
↓

⑨ 输出

  • 完整配音 wav，官方 RTF 0.2065（4090, bf16, kv_cache）→ 10 秒音频约 2.1 秒 官方

B精简版：T2S-only 预生成门控

不训练新模型、不改架构——把推理管线从 T2S 后面切开。只跑①–⑥，数 token 数即得精确时长；通过门控的 token 直接复用，预生成零浪费。

①–⑤ 输入 / 编码器 / 时长编码 论文

  • 与完整版完全相同：同一套权重、同一套参考音频处理
  • 预生成时用自由模式（不指定 T），得到自然时长
↓

⑥ T2S：GPT 自回归生成 论文

  • 只跑到语义 token 序列 S = (s₁…s_T) 就停，不进 S2M
  • 耗时约为完整版的 60–80%（省掉 S2M + 声码器） 估算
↓

⑦ 门控：数 token 我们的设计

  • 预估时长 = T × 标定系数（秒/token，用历史生成数据拟合）——这是精确值，不是估计
  • 对照该段的时间预算： 通过 → token 序列直接喂给 S2M+声码器（预生成的算力全部复用）
    略超 → 用精准模式重跑 T2S（指定 T=预算，模型自动压缩语速）
    远超 → 打回改写译文，不浪费渲染算力
T=247 tokens → 247/49 ≈ 5.04s vs 预算 5.0s → 通过 → S2M(S) → wav
↓门控之后才发生

⑧–⑨ S2M + 声码器（预生成阶段跳过）

  • 只在门控通过后执行，且复用已生成的 token，不重复跑 T2S
  • 被拒的段：省掉 S2M + 声码器全部开销
💡 为什么这是最优的"精简 2.5 只算时长"？时长在 T2S 结束时已成定局——论文的时长编码机制保证的。任何不跑 T2S 的预估器本质上都是在蒸馏 T2S，不可能比 T2S 自己更准。所以"精简"不是训练新网络，而是切管线 + 复用 token。

C蒸馏版：durpred 毫秒级预测网络

换一道题：不生成语音，只预测一个数。输入参数与 infer() 对齐，新音色零样本泛化。

① 输入层（= infer() 参数） 我们的代码

  • text / spk_audio_prompt(wav) / emo_audio_prompt(可选)
  • emo_vector(8维) / emo_alpha / duration_factor / lang
↓

② 文本分支：小 Transformer 我们的代码

  • 字符 embedding(128) + 3 层 TransformerEncoder（并行一次过完全文，非自回归）+ 均值池化 → 48 维
  • 拼接 7 维人工特征：字数 / 标点数 / 数字数 / 句末感叹 / 句末疑问 / 省略号 / 标点占比
(B,L) ids → encoder → mean pool → Linear → R^48
↓

③ 音频分支：DSP 统计，无神经网络 我们的代码

  • 标准库 wave 读 wav → numpy 算 8 维特征：总时长 / 浊音占比 / 有效语音时长 / 音节率估计（能量起音检测）/ 能量均值 / 能量方差 / 起音数 / 过零率
  • 只取与时长相关的语速先验，音色/口音等无关信息主动丢弃 —— 这是能做小的关键
  • 磁盘缓存（按文件哈希），重复音频零重复计算 → MLP 到 16 维
ref.wav → 8 stats → Linear+ReLU → R^16（CPU 约 tens of ms）
↓

④ 情绪分支 我们的代码

  • 情绪参考音频 → 同样 8 维统计；无音频则填 0
  • 拼接 emo_vector(8) + emo_alpha(1) → MLP 到 16 维
↓

⑤ 融合与输出 我们的代码

  • 拼接：48(文本) + 7(人工特征) + 16(音色) + 16(情绪) + 8(语言embedding) + 1(log duration_factor) = 112 维
  • MLP 112→64→1，输出 log(基础时长)，log-domain MSE 训练
  • 最终时长 = exp(输出) × duration_factor（倍率在输出端直接相乘，符合官方行为）
R^112 → ReLU → Dropout → R^1 → exp × df = 预估秒数
↓

⑥ 输出与训练 我们的代码 实测

  • 总参数 0.43M（老师的约 1/2000）；CPU 单句 ~3ms，100 段批量约 2 秒
  • 训练：teacher pairs（IndexTTS2.5 实测时长）→ 回归，早停；1 万条在 5060 Ti 上约几分钟
  • 精度：明显优于字数×系数；长尾（强情绪/怪标点）有偏 —— 定位是粗筛，不是终审
